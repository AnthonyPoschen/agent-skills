# v2026.10.4 - 2026-10-04

## Added

- Added `eyes-on` for a look at a rendered change before that change is called
  done. The skill saves desktop and phone pictures in light and dark, and the
  agent opens those pictures. A DOM query is not this look. Coding and
  `frontend-design` load the skill when a person can see or operate the result.
- Added `create-verification-skill`. It reads a repository and writes a project
  skill that launches the app, drives a feature, and keeps the evidence. The
  feature-map contract lives in that skill. One verification skill per app.
- Added `maintain-verification-skill`. It checks an existing verification skill
  and its feature map against the source and with one live drive. It edits only
  that skill directory and reports a product regression without changing
  product code.
- Added `asd-ste100` for Simplified Technical English in a reply, a document, a
  skill, a comment, a commit message, or a simple explanation. The skill states
  the writing rules and leaves the licensed ASD dictionary out. A project name,
  a path, a command, and a project verb stay. A procedure sentence has a
  maximum of 20 words. A description sentence has a maximum of 25 words.

## Changed

- `eyes-on` fails when a load, a toggle, or a label change moves or resizes the
  control or a neighbor. Sibling actions share size, placement, and motion. The
  control shares a boundary with the thing it changes. That change needs a
  picture from before the action and a picture from after it.
- `frontend-design` uses `eyes-on` for the rendered check. The previous
  browser-use and computer-use steps are no longer the look.
- Coding proves an observable outcome before it calls a change done. A visible
  result also loads `eyes-on`. Creating a project verification skill loads
  `create-verification-skill`. Auditing one loads `maintain-verification-skill`.
  A single change still uses the outcome check.
