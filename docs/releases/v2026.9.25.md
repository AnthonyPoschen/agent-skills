# v2026.9.25 - 2026-09-25

## Added

- Added `test-audit` to decide whether a proposed or existing test should
  exist. It gates new tests and prunes low-value, duplicative, or
  implementation-coupled tests. A subsystem sweep is documented in the skill's
  campaign reference.
- Added `domain-modeling` and `grill-with-docs` for shared terminology, ADRs,
  and a design interview that keeps declared living docs current.
- Added `git-worktree` for creating, synchronizing, and retiring isolated
  worktrees in a mirrored layout.

## Changed

- Coding keeps what a test protects and how it proves that in one Tests
  principle. Whether to add, keep, or remove a test is `test-audit`, including
  a test an agent is about to write. A source-text check counts only when the
  text itself is the contract.
- Coding task files point at shared principles for subtraction, boundaries,
  duplication, and outcome proof. A sequenced workflow finishes every remaining
  phase instead of stopping after the first one.
- `frontend-design` now records substantial decisions in `DESIGN.md`, designs
  from the user's intent, and rejects generic AI visual defaults. It covers
  motion, elevation, contrast, narrow layouts, and loading states that keep
  their settled space. A palette choice can be compared on the real product
  before tokens are kept. Reviews inspect the running interface in both color
  schemes and rank findings.
- `implement-tickets` reconciles merged reviews and closes still-open tracker
  items before claiming the next item. Jira search no longer limits `acli` JSON
  output to the `key` field, which had dropped result rows.
- Docker image builds skip tests that need a cluster or network, and keep tools
  such as `kubectl` out of the final image.
- After a sequenced coding or refactoring phase changes the tree, the commit
  workflow commits that phase and continues.

## Notes

- Comparison base: `v2026.8.25`.
- This release adds and updates skills. It does not require a consumer-facing
  migration.
