# v2026.10.15 - 2026-10-15

## Added

- Added `scripted-verification`. Turn a check that runs more than once into a
  script with a PASS, FAIL, or UNSURE verdict, matching exit codes, and evidence
  on disk. Measure noise before setting thresholds. Pre-check for conflicts, a
  busy resource, or an already-judged commit. Watch for events instead of
  launching or polling agents. New checks start on probation. Coding,
  `context-management`, and `encode-lessons` point to it.
- Added `in-your-own-words`. Before ambiguous or multi-step work, restate the
  goal, problem, constraints, and done check in plain words; flag assumptions
  and open questions; wait for a correction if anything looks off. Inspired by
  poteto's `/in-your-own-words` prompt.
- Added `lint-rules` with seed Go, Rust, and Kubernetes rules. Each seed rule
  has a failing example and a measured keep/loosen verdict. Gotchas become
  repo-local lint rules that explain themselves in the failure message, not
  more docs. Coding loads the skill when a repeated review comment or "don't
  do X" note should become a rule.
- Added `no-comments`, `test-behavior-not-implementation`, and
  `type-system-discipline`, adapted from poteto's pstack with source credit and
  licence status noted. Public API doc comments stay; other comments become
  types, tests, or lint.
- Packaged the repo as a Cursor plugin (`.cursor-plugin/`).
- Added a two-way skills sync script (`scripts/sync-skills.sh`), its tests, and
  `sync-exclude.txt`, so bot boxes and this repo stay aligned.
- Added a Cua Driver MCP installer (`npm run install-cua-mcp`) for local agents.

## Changed

- Rewrote `frontend-design` as concise reminders after it won a blind three-way
  eval against the previous version and a third contender.
- Coding now prefers types, tests, and custom lint over comments, and keeps
  public API doc comments. It also rejects tautology tests that only restate
  the code (`test-audit`).
- First-party `grill-with-docs` and `domain-modeling` now call the glossary file
  `GLOSSARY.md`, matching Matt Pocock skills v1.3.1.
- Delegation handoffs in `context-management` state the goal, done check, proof,
  and constraints instead of prescribing steps.
- Terminal drives in `create-verification-skill` require a normal exit.
- Dockerfile docs note Genos CI self-hosted house runners and the k8s
  promote-genos `GENOS_READ_TOKEN`.

## Removed

- Removed `implement-tickets` from the public catalog. Ticket orchestration is
  no longer published from this repo.
