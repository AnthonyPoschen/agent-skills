# v2026.8.13 - 2026-08-13

## Breaking

- Renamed `implement-all-tickets` to `implement-tickets` so runs can select
  explicit issues, ranges, queries, or a full dependency-linked backlog.
  Install and invoke `implement-tickets` instead of `implement-all-tickets`.

## Added

- Added a standard-library Go supervisor for durable, dependency-gated ticket
  orchestration with isolated checkouts, bounded concurrency, worker ownership,
  resumable state, inbox requests, and sequence-numbered events.
- Added GitHub and GitLab work-source adapters for issue discovery,
  dependencies, review state, inline discussions, checks or pipelines, and
  human-controlled integration.
- Added a fail-closed Jira beta contract for future Atlassian CLI integration.
- Added Codex and OpenCode harness adapters, including Codex workspace
  sandboxing and deny-by-default OpenCode worker policy.
- Added automatic polling and deduplication for review comments, unresolved
  inline threads, requested changes, and CI failures. Feedback that arrives
  during a worker run is reserved for a later follow-up worker.
- Added durable important events for worker launches, AI-generated checkpoint
  commits, pushes, review publication, feedback, failures, blocked queues,
  integration, cleanup, and run completion.

## Changed

- Workers now propose concise Conventional Commit subjects from their actual
  diffs. The supervisor validates them and adds the required `Assisted-by`
  trailer instead of using fixed issue-number subjects.
- Capable harnesses can use the CLI selectively for tracker state,
  deduplication, dependency gates, recovery, events, and publication while
  retaining native agents, sandboxing, reasoning, and progress UI.
- Project preflight now discovers repository conventions and fails with grouped
  setup questions when target branches, labels, verification, or tracker
  contracts cannot be established safely.

## Fixed

- Human feedback is accepted when the reviewer uses the same account as the
  supervisor; agent-authored comments remain excluded by the required
  `AI-generated:` marker.
- Review publication retries eventual-consistency reads until the provider
  reports the pushed head commit.
- One supervisor now owns a run for its full lifetime, preventing old and new
  managers from alternating between polling cycles.
- A completed run now stops workers, removes verified clean run-owned
  checkouts and their empty root, retains audit logs outside those checkouts,
  emits `run_completed`, releases ownership, and exits. Human-closed unmerged
  reviews terminate distinctly as `review_closed`.
